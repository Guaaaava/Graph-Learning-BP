## 1. 实验设置

| 参数 | 值 |
|------|-----|
| GNN | EdgePredictorGNN, 5->64->64->1, 3层 MessagePassing + 残差 |
| 节点特征 | [pos_x, pos_y, sigma2_x, sigma2_y, is_anchor] (5维) |
| 边特征 | [measurement, variance, pseudo_range_residual, is_anchor_edge] (4维) |
| 粒子BP | K=10000, iter=3, sigma_meas=0.5, init_cov=25 |
| 损失函数 | L = log det(J^{-1}) + lambda*KL(p||q) + eta*sum ReLU(3-D_i) |
| 固定参数 | GAMMA=0.002, FIM_PRIOR=0.5, SPARSITY_WEIGHT=0 |

## 4. 分析与讨论

### 4.1 核心发现: Normal/Hard 无冗余，Challenge 首次出现有效压缩

| 场景 | Dense 边 | GNN 边 | 压缩率 | RMSE 比 | 模式 |
|------|---------|--------|--------|---------|------|
| normal | 166 | 161 | 2.9% | 1.017 | 无冗余边可剪 |
| hard | 148 | 143 | 3.5% | 1.022 | 无冗余边可剪 |
| **challenge** | **379** | **302** | **20.3%** | **1.172** | **有效压缩!** |

**关键洞察**:

1. **Normal/Hard 场景确实没有冗余**: ~150 条边在 ~30 个 agent 中，几乎每条边都携带独特 Fisher 信息。GNN 正确地选择保留几乎所有边。

2. **Challenge 场景首次展现 GIB 的压缩能力**: 锚点通信半径扩大 1.8x 后边数膨胀到 379，其中 15% 是 NLOS 噪声边。GNN 识别并剪枝了 77 条边 (20.3%)，RMSE 从 1.57 升到 1.84 (仍远优于 BFS 的 4.79)。

3. **GIB 思路被验证为可行**: 在存在冗余边(NLOS/噪声边)的场景下，GNN 能有效区分高质量边和噪声边，实现压缩同时保持可用精度。

- 三场景 GNN RMSE 与 Dense 差距 < 3%，GIB 有效保留了定位关键边
- 边压缩仅 2-6%: FIM 项 (~-55) 远大于 KL*lambda (~8) + degree (~1)
- 所有传统 baseline 无法同时兼顾精度和压缩
- 三场景 grid search 均选出 minimal lambda=20，说明模型天然倾向低压缩

### 4.2 分析

1. **FIM 主导问题依然存在**: FIM=-55 vs KL*20=8, 压缩压力不够。提高 lambda 可能进一步增加压缩率。
2. **Challenge 场景为 GIB 提供了冗余边**: 扩大通信半径 + NLOS 注入创造了"值得剪的边"
3. **网格搜索局限**: 30 epoch 不足以让大 lambda 找到好的压缩策略，需要更多 epoch
4. **Dense challenge RMSE(1.57) < normal RMSE(2.27)**: 通信半径扩大后测距更多定位更准，但代价是 379 条边的通信开销

### 4.3 改进方向

1. **增大 lambda 在 challenge 上测试**: 50-200 可能进一步压缩到 50%+
2. **在正常通信半径下注入更高比例 NLOS**: 15% -> 30-50%
3. **增大图规模**: Agent 数 30->100, 创造更多冗余
4. **Lambda 退火策略**: 训练前期小 lambda 保精度，后期大 lambda 促压缩

1. **FIM 绝对主导**: FIM=-55 vs KL*20=8, 优化 FIM 的收益远超压缩
2. **小图低冗余**: ~30 节点 ~150 边，每条边携带独特 Fisher 信息
3. **30 epoch sweep 不够**: 大 lambda 可能需更长训练才能找到好的压缩策略
4. **场景设计偏保守**: 即使 challenge 也只有 15% NLOS，大多数边仍有用

### 4.3 改进方向

1. **增大 lambda**: 尝试 50-500，或使用动态调度 (前期小 lambda, 后期大)
2. **归一化损失**: FIM 和 KL 量纲不匹配, 加自适应权重
3. **增大图规模**: Agent 数 30->100, 增加冗余边供剪枝
4. **NLOS 监督**: challenge 场景可利用 NLOS 标签提供显式剪枝信号
5. **更难的场景**: 极端 NLOS (50%+), 更少锚点 (2-3个), 更大的通信半径
