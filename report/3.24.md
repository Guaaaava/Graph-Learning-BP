# 会议纪要

1. 过度自信倍率是什么指标？

- a. BP 算法的结果中，每个节点都有一个协方差矩阵：$$\Sigma=\begin{bmatrix}
\sigma^2_x&\sigma_{xy}\\
\sigma_{yx}&\sigma^2_y
\end{bmatrix}$$ $\sigma^2_x$ 是 $x$ 轴方向上的方差，$\sigma^2_y$ 是 $y$ 轴方向上的方差，$\sigma_{xy}=\sigma_{yx}$ 代表 $x$ 和 $y$ 的协方差，描述概率云椭圆的倾斜方向。如果 $\sigma_{xy}>0$，误差是正相关的。如果算法把你向东边（X 增大）估偏了，那大概率也会把你向北边（Y 增大）估偏。反映在图上，你的误差椭圆是向“右上-左下”倾斜的。

- b. 从几何上看的真实误差（均方误差 MSE）：在一次具体的定位中，算法估计的坐标 $(X, Y)$ 距离真实坐标有多远？根据勾股定理，真实欧氏距离的平方 $D^2$ 是：$$D^2 = (X - \mu_x)^2 + (Y - \mu_y)^2$$

- c. 从统计上看算法的预期：$D^2$ 的数学期望是$$E[D^2] = E[(X - \mu_x)^2 + (Y - \mu_y)^2]$$根据期望的线性性质（加法的期望等于期望的加法），我们可以把它拆开：$$E[D^2] = E[(X - \mu_x)^2] + E[(Y - \mu_y)^2]$$在统计学定义中，$E[(X - \mu_x)^2]$ 恰恰就是 X 的方差 $\sigma_x^2$！同理，$E[(Y - \mu_y)^2]$ 就是 Y 的方差 $\sigma_y^2$！所以，等式变成了：$$E[D^2] = \sigma_x^2 + \sigma_y^2 = Trace(\Sigma)$$因此两个可以相比。

- 建议使用 NEBP 论文中的“consistency analysis”代替“过度自信倍率”

2. consistency analysis:

- 使用的是归一化估计误差平方 (Normalized Estimation Error Squared, NEES)，公式为 $e_{i,n}=(\hat{p}_{i,n}-p_{i,n})^{T}\hat{\Sigma}_{p,i,n}^{-1}(\hat{p}_{i,n}-p_{i,n})$ 。假设真实的后验分布是高斯的，NEES 服从自由度为 2 的卡方分布。

- 我们之前的 MSE / Trace 只是一个直观的“平替”，而 NEES 在数学上要严谨得多。

- 1. 考虑了误差的“方向性”： Trace（迹）只把 X 轴和 Y 轴的方差简单相加，把它当成了一个正圆 。但真实的协方差 $\hat{\Sigma}_{p,i,n}$ 包含非对角线元素（协方差），误差圈通常是一个倾斜的椭圆。

- 2. 马氏距离的降维打击： NEES 公式本质上计算的是真实坐标与估计坐标之间的马氏距离 (Mahalanobis Distance)，因为它乘以了协方差矩阵的逆 $\hat{\Sigma}_{p,i,n}^{-1}$ 。如果算法在某个方向上自认为很准（方差极小，$\Sigma^{-1}$ 极大），但实际误差却落在这个方向上，NEES 会把这个误差呈指数级放大，狠狠惩罚算法的盲目自信。

- 3. 具备严格的统计检验标准： 因为 NEES 服从卡方分布，论文可以通过双侧卡方检验（设置置信区间，如 95%）来科学地判断一个假设 $H_0$（算法估计是一致的）是否被接受 。在图 2(c) 中，理想情况下，在置信水平为 $1-\alpha$ 时，接受假设的概率也应该是 $1-\alpha$（即那条黑色的虚线） 。

3. BP 在环上的问题有哪些？

- **缺陷一：信息回音室与数据乱伦 (Data Incest / Rumor Routing)现象**： 这就是导致“过度自信”的罪魁祸首。

- 原理： 假设 A 告诉 B：“我在你左边 2 米”。在有环图里，B 会把这个信息传给 C，C 传给 D，D 最终又绕回传给了 A：“我听说你在我左边 2 米”。A 收到后大喜：“哇！D 也这么觉得！现在有两份独立证据证明我在这了，我越来越确信了！”但实际上，这根本不是新证据，这只是 A 自己说的话在环路里转了一圈又回来了。BP 算法无法识别这种“回音”，导致它把同一份测距信息重复计算了无数次，方差（Trace）被无限缩小，陷入极度的过度自信。

- **缺陷二：收敛困难与震荡 (Oscillation and Non-convergence)现象**： 在稠密图上，节点位置的信念（Belief）会在几次迭代中来回跳跃，甚至永远无法稳定下来。

- 原理：高斯 BP 只有在“树状图 (Tree-structured Graph)”上才能在数学上保证收敛到精确边缘概率。 在短环路极多的稠密图里，互相矛盾的测距噪声会在短环里形成局部的“推拉博弈”。节点 A 刚被 B 拉过去一点，下一轮又被 C 拉回去了。你的算法可能跑了 50 轮还在震荡，根本拿不到一个确定的定位结果。

- **缺陷三：通信与计算开销爆炸 (Communication Overhead)现象**：极其耗电。

- 原理： 在无线传感器网络中，发送和接收无线电波是最耗电的。如果网络有 $E$ 条边，每轮迭代就要发送 $2E$ 条消息。如果是 100 个节点的全连通稠密图，边数可能高达几千条。节点为了发这些互相重复的“废话（冗余消息）”，电池很快就会被耗尽。
