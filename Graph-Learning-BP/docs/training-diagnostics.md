# 训练时记录什么、怎样判断裁剪和衰减

本地接入：2026-11-04。此阶段增加观察记录，不改变原有损失、反向传播、梯度裁剪或 AdamW 更新。裁剪阈值仍为 5，权重衰减仍为 1e-4；是否必要继续等待正式短训练和受控对照。

## 记录位置

| 文件/字段 | 内容 |
| --- | --- |
| 运行目录下 diagnostics/epoch-0001/batch-00001.json | 每个成功训练批次的损失、选边、梯度及更新统计 |
| history.json 每轮的 train_diagnostics | 批次统计汇总，随完整检查点保存 |
| history.json 的 train / val / val_deterministic | 已有损失分项及两种验证结果；温度、学习率继续在每轮记录 |
| diagnostics/failures/epoch-…-batch-…-attempt-….json | 失败阶段、样本编号、异常和已获得的数值记录；重复失败另存，不覆盖 |
| run.json / 完整检查点中的 training_diagnostics | 日志格式、统计范围与阈值约定 |

批次是一次优化器更新，不是单张图。每轮对梯度和更新统计取批次等权平均、50/95 百分位和最大值；图结构的均值按实际图数加权，避免最后一个小批次被过度加权。概率均值及接近 0/1 的比例按物理边统计，另报边数。

## 梯度与裁剪

| 直观含义 | 批次字段 |
| --- | --- |
| 裁剪前梯度有多大 | gradient.returned_pre_clip_norm；另记 float64 测量值 measured_pre_clip_norm |
| 梯度被缩小了多少 | gradient.clip_scale，1 表示没有缩小，0.2 表示约缩到原来的五分之一 |
| 裁剪后有多大 | gradient.post_clip_norm |
| 是否发生裁剪 | gradient.clip_applied；每轮 clipped_steps / steps 得到 clip_fraction |
| 是否有 NaN/无穷或参数没有梯度 | gradient.nonfinite_elements / parameters_without_gradient |

裁剪前的主范数直接取现有 clip_grad_norm_ 的返回值，不再次执行裁剪。实际缩放沿用原函数的 min(1, limit/(norm+1e-6))；保留原有误差保护。由于这个 1e-6，接近阈值时“实际被缩小”与“范数严格大于阈值”可能略有区别，后者另记 norm_above_threshold。

非有限梯度仍由原有 error_if_nonfinite=True 停止，新增日志只留证，不替换成零、不跳过后假装成功。失败日志将非有限数值写成 null，另用 nonfinite_fields 明确标出 nan/inf，保证 JSON 可以正常读取。历史中成功轮次的非有限计数为零，不代表整个运行从未失败；需同时查看 failures 目录。

频繁裁剪说明优化器经常收到被缩小的梯度，但不能单独说明阈值应该升高/降低，也不能证明训练已不稳定。需要结合损失系数、学习率、温度、实际更新量和验证表现判断。

## 参数更新与权重衰减

| 直观含义 | 批次字段 |
| --- | --- |
| 参数整体有多大 | update.parameter_norm_before / parameter_norm_after |
| 这次更新实际改动多少 | update.actual_step_norm，即更新前后参数差的 L2 长度 |
| 改动相对参数规模有多大 | update.relative_step_norm；参数原长度为零时记 null |
| 使用的学习率、衰减和参与更新参数数目 | update.groups |
| AdamW 衰减的名义缩减量 | update.nominal_adamw_decay_norm，按更新前参数计算 lr*weight_decay*parameter，仅计有梯度的参数 |
| 名义缩减量与实际总更新量之比 | update.nominal_decay_to_actual_step_ratio，总更新为零时记 null |

名义衰减长度不是“不使用衰减会怎样”的实验结果，也不是实际总更新中可相加的百分比；梯度更新与衰减方向可能抵消，因此比值可以大于 1。只有保持其余设置、数据和种子相同，对比有/无衰减的训练与验证结果，才能研究它是否有益。

没有梯度的参数不参加当前 AdamW 衰减；零梯度张量与“没有梯度”不同，前者仍可能被衰减。日志对此分别计数，解析小例子已检查这一点。实际更新差先取浮点参数保存值之差，再以 float64 求长度；没有重算、替换优化器更新。

参数副本只在当前批次的更新前后暂存于内存，不保存到每个批次文件；没有额外优化器步骤或额外反向传播。GPU 上的同步、范数计算、参数副本和磁盘写入仍有开销，需服务器短试实测，不宣称零开销。

## 选边和损失

记录实际随机选出的边数、保留比例、通信成本、智能体三角形数、度数不足 3 的节点数及缺口。同时记录候选图本身无法避免的缺口，例如某智能体原图只有 2 条边，模型删边策略无法消除至少 1 的缺口。

概率小于 0.01 / 大于 0.99 仅定义“已接近 0/1”的诊断区间，不参与选边、过滤样本或优化。实际选边继续由原模型采样；这些统计也不保证连通、刚性或定位精度。

没有候选边的图仍计入图数、成本和度数统计；其边保留比例/概率均值因没有分母而为 null。汇总保留比例时明确给出有候选边的图数，不把 0/0 当成 0 或 1。

各分项损失沿用现有记录，包含任务、压缩、通信、三角形、测量保留及度数等。分项值不是各项对参数更新的贡献；本阶段不为每一项额外反向传播。温度、学习率和验证日志保持上一阶段规则。

## 恢复与适用范围

成功批次记录在更新完成后原子写入；失败位置可能在前向、目标、反向、裁剪、优化器或日志写入。optimizer_step_started 表示开始调用，optimizer_step_applied=false 表示尚未调用、true 表示调用已返回；若优化器调用中途抛错则为 null，不保证参数完全未动。

批次日志不是批次检查点。中途失败仍只从最近完整 epoch 恢复，重新执行该轮；已有相同位置的成功日志会以重放结果原子写回，失败 attempt 记录保留。不能根据“已有第 5 批日志”直接从第 6 批继续优化。

检查点继续使用 v2，日志另带 training-diagnostics.v1 标识。旧 v1/v2 检查点仍可读取/评估/初始化；更新了源码后不能直接恢复旧运行，需原源码或另开运行。新日志模块纳入训练源码摘要，带日志的检查点会核对格式和历史计数。日志没有墙钟时间等不确定值，便于比较连续训练和恢复训练是否一致。

本地微型 CPU 软件检查不能决定正式训练是否需要裁剪/衰减，也不替代远程 GPU 验收。2026-11-05 后续已完成 [论文版本审阅](paper-version-review-20261105.md)，旧摘要保留并追加当前稿登记；论文正文和数学核心未改。完整 CPU 验收以该阶段报告为准。
