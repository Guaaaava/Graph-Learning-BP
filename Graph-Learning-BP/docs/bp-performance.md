# BP 性能检查与第一轮独立缓存实验

日期：2026-11-10。本阶段仅准备本地实验代码、CPU 数值检查和微型计时。
生产 `ParticleBP`、正式训练/评价入口、配置和正在运行的服务器任务均未改动。

## 实现与边界

- `tools/bp_cached.py`：实验子类，仅替换粒子对消息计算。继承原图检查、固定先验支持、同步 cavity 递推、锚点项、归一化、矩估计、阻尼与停止规则。
- 每个 `infer()` 内缓存固定距离对应的**对数似然块**；每轮仍使用当轮 cavity 重新做 `logsumexp`。两个消息方向沿用原实现的同块共享，不能将其计成新增优化。
- 上限约束缓存张量的有效载荷，不等于总显存上限。保存先遇到且装得下的块；其余重算，无淘汰策略。缓存不跨推断调用、不跨模型；跨模型共享尚未实现。
- 不降低粒子数/轮数/精度，不增加似然底噪，不重采样，不改求和为可能下溢的概率域乘法。缓存块只读，成功和异常出口均释放。
- `tools/bp_benchmark.py`：默认只输出计划；仅显式 `--execute` 才执行，只读取已有 **val**，不生成数据、不读取正式 test、不接入历史候选任务缓存。

P10000 时，一条边完整 FP64 似然约 800,000,000 字节（0.8GB，约763MiB）。4GiB 只能装约5条边，12GiB约16条；存在分块边界影响。不能从小样例的全缓存效果外推正式图收益。

## 如何检查正确性

1. 同一输入、同一支持、同一掩码，比较旧版和实验版各轮消息、权重、均值、协方差和最终 ESS。
2. 小树用独立全联合枚举检查有限支持后验；环图比较同轮旧实现，不把环上 BP 等同精确后验。
3. 包含非均匀/零先验质量、极小似然、退化协方差、别名支持、断开图、缓存装不下、中途异常清理及跨调用输入变化。
4. GPU 短测另比 CPU/GPU；该项本地无 CUDA，尚未运行。

GPU 工具固定数值比较上限 rtol=1e-8、atol=1e-9，可收紧、不可放宽；另检查覆盖判定、协方差状态、可达性和迭代/停止判定。记录最坏差异，任何不符即停止，不允许靠放宽阈值把失败变成通过。源码、模型、验证数据、输入、掩码和支持摘要均保存。

## 如何检查速度

- 计时前后同步 GPU；只计完整 `infer()`，**包含本次缓存构建**；支持生成、加载与指标单独在计时之外。缓存每次重建，不预热成免费缓存。
- 每个条件默认重复2次。第0次作为冷启动留档，速度汇总只使用后续重复；首轮仅1次热计时属探索性估计，需要再复测确认。
- 以相同图/拓扑的完整热重复配对，用各案例中位时间之和的比值汇总，不平均各图提速比例。
- `--profile` 单独输出算子表与时间轨迹，其时间包含测量开销，**不用于提速结论**。
- 保存 PyTorch 分配显存峰值及相对推断前增量；不将其冒充整卡监控占用。缓存上限不是总峰值。
- 默认每次调用最多12次推断、3600秒；只在推断边界检查，单次可能越过时间上限。逐项落盘，`--resume` 核验身份后续跑，不强杀、不自动变更方案。
- CUDA 执行前若发现其他GPU计算进程则拒绝开始。正式测试前还需确认资源无竞争，短测只在当前任务结束后安排。

## GPU 检查的建议顺序（尚未执行）

先核对冻结源码与运行环境，在**独立实验副本**中放置新增文件，保留原任务目录。不能直接替换 `gib4cl/inference/particle_bp.py`，不能覆盖历史报告或检查点。

第一批只测 Dense/BFS、验证图0和6、BP种子700、P10000/T10。比较原2048分块与两个实验条件；缓存上限先用4GiB，观察峰值后再决定扩大。以下命令从实验副本项目根运行，输出目录必须全新：

```bash
python -B -m tools.bp_benchmark \
  --config configs/experiment.json \
  --data-root /root/autodl-tmp/gib4cl-work/night-candidates-screen-20261106/workspaces/candidates/data \
  --graphs 0,6 --particles 10000 --iterations 10 --reference-chunk 2048 \
  --variant 2048:4096 --variant 4096:4096 --repeats 2 \
  --max-inferences 12 --max-seconds 3600 \
  --output /root/autodl-tmp/gib4cl-work/bp-performance-gpu-timing-20261110 \
  --execute
```

共24次推断，首批最多12次；相同命令追加 `--resume` 完成剩余部分。此时应核对待运行工作量，而非无限自动重复。该24次中2个图×2个拓扑×3个实现×2次重复；不含学习模型。

性能分析先缩短到2轮，只定位算子成本，不作为T10验收和耗时结论。如下前2次仅测图0 Dense 的原版与零缓存带标签实验版，避免一次采集完整长面板：

```bash
python -B -m tools.bp_benchmark \
  --config configs/experiment.json \
  --data-root /root/autodl-tmp/gib4cl-work/night-candidates-screen-20261106/workspaces/candidates/data \
  --graphs 0 --particles 10000 --iterations 2 --reference-chunk 2048 \
  --variant 2048:0 --repeats 1 --profile --max-inferences 2 \
  --output /root/autodl-tmp/gib4cl-work/bp-performance-gpu-profile-20261110 \
  --execute
```

确认数值、资源和速度后，再补两组原验证最佳模型的训练种子101代表；用 `--models-json` 提供已核对的模型清单，`--checkpoint-root` 指向原只读候选工作区。工具核对检查点摘要和验证数据身份，不训练或更换模型。学习模型不能用 Dense/BFS 的加速结果代替。

若候选变慢、显存不足或数值不符，保留失败证据，不自动继续提高缓存、改精度或访问测试。阶段结果共同审阅后再决定是否做计算融合、跨模型共享或修改评价重复预算。

## 本地结论如何使用

小规模 CPU 计时只能说明工具可执行与特定 CPU 样例的表现。即使缓存使距离计算减少到原来的十分之一，消息求和仍需10轮，总体加速不会自动达到10倍。500图的GPU成本须等服务器同预算实测后重新估算。
