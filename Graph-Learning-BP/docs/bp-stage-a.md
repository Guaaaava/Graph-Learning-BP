# 阶段A：本地性能准备工具

本阶段不连接服务器、不运行GPU、不训练、不读取正式test。生产推断代码和已有性能缓存实现均未改动；新增工具准备后续测量、联合实现的独立参照与资源方案。

## 联合执行契约和CPU参照

`tools/bp_joint_reference.py`：

- `prepare_joint(data, masks, model_ids, support)`：同一图、同一支持，掩码形状 `(模型数, 物理边数)`；拷贝输入并记录摘要，提供每条边涉及的模型列表。
- 可共享粒子坐标、距离和测量似然；各模型的锚点项、cavity、消息、权重与矩保持独立。每模型沿原物理边顺序保存消息，两方向布局与原实现一致。
- `joint_cpu_reference(...)`：独立NumPy对数域同步BP，完整似然每条并集边只生成一次；禁止大数相减构造cavity。小树另与全联合枚举参照核对。
- 仅供小图参照：CPU、float64、最多512粒子、默认最多200万似然元素，无阻尼/提前停止/底噪。不是可直接使用的正式GPU后端，不用它宣称运行加速。
- `JointProblem.verify()` 拒绝准备后被改动的输入；原调用者修改自己的张量不影响已拷贝问题。输出保留每模型及每轮状态，未来联合GPU实现应逐项与其比较。

## 统计和计时

`tools/bp_timing.py`：

- `panel_ledger(paths)` 仅收完整val粒子BP报告。身份包含图/输入/支持、掩码、模型检查点、预算、精度、评价配置及BP源码；数值冲突报错。
- 相同缓存记录重复出现在多个报告只计一次。相同推断身份下不同的真实计时保留为不同计时观测，不冒充独立科学样本。
- 按图、方法、边数、训练与粒子种子汇总；保留最慢案例。不同预算/设备需在比较时分开，不能把历史代理评价或CPU样例混作GPU性能证据。
- 原报告只有 `inference_seconds`，加载、支持、指标、保存均标记为未知；不能用总时间减去几个已测值伪造分项。
- `PhaseTimer` 提供未来运行器的互斥分项钩子。可由调用者传入GPU同步函数；端到端时间另计，未插桩部分明确保留。尚未注入正在运行的任务或原评价入口。
- `benchmark_pairs` 排除冷启动和带分析开销的记录，用相同案例的热重复中位耗时之和比较，不平均各图速度比。

## 成本与分片

`tools/bp_cost.py` 是离线规划器，不打开数据或模型、不信任实际任务缓存、不提交或租用资源。

`workload` 接受图索引、BP种子、每方法的训练种子、测得的单次推断时间、已测或未知的额外时间、逐方法提速假设及科学身份。Dense/BFS等基线不允许按训练种子重复。额外图集与种子先集合去重，不能重复收费/计量。

`estimate` 只对推断部分应用加速倍数，保留已测加载等开销；给出工作量、规划等待时间、设备小时、可选费用及明确的余量假设。缺失开销未测，不将1.3余量冒充置信上界。计时输入来自旧模型时，必须标记为预算示例而非最终测试预测。

分片按预计较慢图优先分配，整张图的所有方法与BP种子在同一设备；保存每片图和单元ID，输出独立目录。`validate_merge` 拒绝缺项、重复、错误设备、身份或输入/支持不一致。该函数仅验证交付契约，不是已完成的多卡调度器，也不验证伪造的文件摘要；实际执行还需原始文件核验和逐项落盘/恢复接入。

## 固定样例与原数据核验

`tools/bp_sample_plan.py`：初筛固定图0/6，扩展包含已记录困难图5，以及32图按Dense智能体边数分位数和覆盖间隔选择的图，总计8图。规则与索引在GPU测速前保存，不使用新运行时间、RMSE或覆盖率挑图。

本地PyTorch2.7.1/Windows重建输入与服务器历史摘要不一致。现有16图真值和边数一致不能证明完整输入一致，也不能据此断言差异仅为舍入。阶段A保存的32图副本只服务结构规划，**不能替代服务器原500图验证集**。

阶段C先在原环境读取原文件，然后执行核验：

```python
from gib4cl.runtime import load_split
from tools.selection_state import read_json
from tools.bp_sample_plan import verify_original_val

# cfg为冻结配置，data_root指向原服务器工作区data目录。
dataset, identity = load_split(cfg, 'val', data_root)
verification = verify_original_val(read_json(fixed_samples_path), dataset, identity)
```

该检查绑定原数据文件/数据集/系列/配置身份；有历史原图输入摘要的样例必须匹配。其他图记录原文件中实际生成的输入摘要，并检查预登记结构。核验结果保存后才能运行GPU短测；不通过则先查输入与环境，不能放宽成“近似相同”。

## 可复现本地准备

从具有阶段报告的本地项目根执行，下列输出目录必须全新。默认不加 `--execute` 只显示计划，不创建输出或重建图：

```bash
python -B -m tools.bp_stage_a \
  --workspace-root /path/to/GIB4CL-Experiment \
  --output /path/to/new-stage-a-output --execute
```

构建器明确限定五个历史阶段、12份原始面板，核对生产源码与先前本地参照一致。输出统计、固定样例、CPU数值参照、两份原最佳模型清单、模型/推断复用索引、成本示例、分片交付例和缺失证据清单；不下载权重、不访问服务。

正式采用仍须阶段C的原输入、GPU数值和资源验收。阶段A完成不意味着GPU已实现2–5倍加速，也不表示正式测试已压到30小时。
