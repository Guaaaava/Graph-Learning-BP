# 如何验证模型、挑选训练中最好的一轮

规则确定及本地接入：2026-11-04。只影响验证与保存模型，不修改论文损失、选边模型、优化步骤或粒子 BP。

## 采用的规则

每轮训练结束后，在同一份完整验证集上执行：

1. 模型进入评估模式，读取每条边的保留概率；不更新参数、不计算梯度。
2. 对每张图随机决定哪些边保留，重复 16 次。保留概率为 0.7 的边每次有 70% 的机会保留，并不保证 16 次中恰好保留某个固定次数。
3. 用论文中的原目标计算每次损失，先对该图的 16 次取平均，再对验证图等权平均。节点多的图不会仅因为节点多而获得更大的图间权重；图内损失仍按论文求和，不改目标。
4. 以这个平均验证总损失挑选最好的一轮。只有严格降低才更新最好模型，完全相同时保留较早的一轮；不使用任意“差不多”的隐藏容差。
5. 另算一次“只有保留概率大于 0.5 才保留边”的验证结果作为部署对照，不参与上述选模。恰好为 0.5 时删除。如果配置的部署门槛改变，对照会随配置改变并写入记录，主随机平均规则仍不依赖门槛。

每张图的随机数由验证种子 1700、sample_id、重复编号共同确定；不同轮次复用同一套抽签号码。模型概率变化后，抽签号码相同也可以产生不同保留结果。这样减少因“这轮恰好抽得好”产生的比较波动。

训练到 20、60、200 轮都使用同一份已加载验证集；正式场景通常为 500 图。前 64 图只能用于事后比较不同候选的轻量诊断，不在续训途中替换主验证集。切换图范围、重复次数或验证种子会改变比较标准，需要新运行，不能继续沿用旧的最好值。

## 为什么这样选

论文训练目标对随机选出的边求期望。多次随机选边后的平均值直接近似这个目标；按 0.5 门槛只选一次图，回答的是确定部署规则的表现。将前者用于同一组系数内挑选轮次、后者单独观察，使二者作用明确。

这不是论文之外的新定位算法或新目标，只是估计已有随机目标并确定保存哪个模型的实验规则。温度不改变硬选边样本的分布，验证中的采样固定 tau=1，只用于得到硬掩码，不参与梯度。

16 次和种子编号 1700 是可复现的计算约定，没有“16 次必然足够”的理论保证。每轮同时记录前 8 次的平均总损失及它与 16 次均值之差，供后续观察抽样敏感性；不能事后从 8/16 中挑有利结果。正式训练前仍需服务器试跑测成本，训练后需检查有限抽样是否影响主要判断。

本次两图、两轮的微型 CPU 流程中，前 8 次均值偏好第 1 轮，16 次均值偏好第 2 轮。它不能代表正式 500 图的情况，但足以说明不能把“功能正确”写成“抽样次数已充分”。主规则仍按预先约定的 16 次执行，不根据此例挑有利轮次；正式选参前的服务器短试需复核成本及抽样敏感性。

固定模型、未用这些随机样本选它时，随机平均针对现有目标的期望；对已经按该验证结果挑过的最好模型，不再声称它是独立无偏的性能估计。最终性能仍需冻结配置后的 test 和独立训练种子。这里也没有使 STE 梯度变成无偏梯度。

## 保存和恢复

| 输出 | 含义 |
| --- | --- |
| history.json 中 val | 16 次随机选边的图等权平均损失和各分项，用于选模 |
| val_deterministic | 按部署概率门槛选边的损失和各分项，只作对照 |
| val_sampling | 重复次数、前一半重复的平均总损失及差值 |
| best_checkpoint.pt | 当前规则选出的最好一轮完整状态 |
| last_checkpoint.pt | 最近一轮状态，用于精确续训 |
| run.json / 检查点中的 validation_protocol | 规则版本、图数、重复次数、验证种子、平均方式、部署对照门槛等 |

新完整检查点使用 gib4cl.checkpoint.v2。加载时核对规则、配置、历史中的有限损失和最好轮次；恢复还要求原始源码、数据、设备/环境和训练日程一致。验证采样模块也纳入源码摘要。

旧 v1 检查点继续支持读取、评估和作为新训练的初始权重。它采用旧验证含义，不能用新代码直接续训；需回到原代码环境恢复，或用 init-from 开始新运行并重新记录验证历史。历史实验文件不迁移、不改名伪装成新规则结果。

## 与比较不同系数的关系

同一组 beta/gamma/kappa/eta 内，可以用总损失挑轮次。不同组总损失的权重不同，不能据此选超参数；仍按 [选参协议](selection-protocol.md) 比较定位、协方差可信度和通信等共同指标。

本次不接入每轮粒子 BP，不新增高斯提议、重采样、阻尼或粒子修复。验证只使用训练目标原有的高斯预测器。

## 检查条件和边界

- 对两条边的四种保留组合独立枚举，检查平均损失和 p=0.5 的门槛行为。
- 固定样本重复可复现，增加重复次数保留原前缀；评估模式、参数和训练随机状态不受验证采样影响。
- 图顺序、最后小 batch、图大小和 batch 划分不改变图等权结果。
- 故意让两种验证指标偏好不同轮次，检查实际按随机平均选模；相同均值取较早轮次。
- 检查完整训练和中断恢复的模型、优化器、调度、历史、随机状态及最好轮次一致；更改规则应拒绝恢复。
- 本地 CPU 测试不代替远程 Python3.12/PyTorch2.8/CUDA12.8 的 GPU 验收，也不证明 16 次足以稳定所有正式候选的排序。
