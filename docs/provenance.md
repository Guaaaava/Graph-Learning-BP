# 来源、历史归档与便携校验

## 当前来源

论文依据为 GIB-Chap234-1016.tex 第 2、3、4 章。源仓库中的论文未因本次整理而修改。生产算法集中在 gib4cl；完整旧→新映射见 [source-layout.json](source-layout.json)。

[tests/fixtures/provenance.json](../tests/fixtures/provenance.json) 从之前已经验证的不可变快照生成，记录：

- GNN、论文目标、粒子 BP 的原始文件 SHA-256 与去除导入后的完整 AST 摘要；
- 移除固定模型/BP 标签后，从可信原始源码推导的完整当前 AST 摘要；
- 清理前六份历史预设的数据指纹（仅历史记录，不是当前配置的指纹）；
- 论文 SHA-256、原始/整理前快照 SHA-256；
- 八个原始 NEBP 源文件哈希。

工具据此核验当前代码，并重跑独立数学与流程参照。这份数据本身列入发布包逐文件校验清单。

模型和 BP 标签的清理由原始 SHA-256、原始完整 AST 与限定的历史投影共同核验：历史模型只移去版本属性及专用权重状态包装，历史 BP 只移去版本属性、工厂版本条件和诊断版本字段。当前源码一律比较完整 AST 摘要，不对当前代码忽略这些位置；数学公式改变或额外注入代码仍会失败。原始摘要保留，未被当前摘要替换。

2026-10-28 的配置清理保留上述数学核心；当前生产输入只使用五锚点均匀 LOS 场景，生成配置与数据指纹已经改变，历史指纹不再用作当前预设的匹配断言。旧数据、配置和检查点不自动迁移。实际数据身份由当前配置、完整指纹、样本元数据和文件校验值共同确认。

## 历史区

源仓库 legacy 保留以下内容，全部排除出发布包：

- compat：先前 GNN_learning、BP、NBP_ST 的旧导入/启动兼容层；
- config_constants.py、fim_objective.py：历史常量和未作为当前目标使用的旧 FIM；
- references/NEBP：用户提供的原始外部参考源码；
- audits：旧阶段脚本，作为记录保留；
- snapshots：第一步及目录整理前的不可变快照；
- records、docs、manifests：旧冻结证据、原文档和搬移前文件清单；
- results：原有历史产物目录。

历史区不维护为当前运行入口。归档的旧兼容脚本不再通过默认 sys.path 提供旧顶层模块。需要当前实验请运行 python -m gib4cl，需要追溯旧行为应查对应不可变快照。

## 发布包如何独立验收

发布包不携带 legacy，也不要求本机存在 NEBP 源码或旧阶段 ZIP。它使用冻结身份数据及当前可执行独立数学参照；若源仓库本地仍存在历史目录，来源工具会额外逐字核验对应档案并在 scope 中记录。

因此，“仅根据冻结来源数据核验”和“还核验了本地历史档案”在报告中明确区分。源码包模式不能声称现场检查了未打包的 NEBP 执行文件。

源码包无自己的 .git 时，数据来源记录中的 git_head 为 null，即使它解压在另一个 Git 仓库内部也不会误记父仓库版本；实际源码身份以逐文件哈希和包清单为准。

.gitattributes 固定当前文本为 LF，legacy 保留原始字节，避免跨系统检出时无意改变历史档案。
